# 🎭 novel-agent-platform

多角色小说写作智能体平台。6 个 Agent 角色 + LangGraph4j 状态图编排，**模型配置 100% 页面化**，每个角色可独立绑定 LLM endpoint，无需重启即时生效。

> 📖 使用操作手册见 [USAGE.md](USAGE.md)

---

## ✨ 特性

| 特性 | 说明 |
|---|---|
| **6 角色智能体** | 🌍 世界构建师 · 📐 大纲设计师 · ✍️ 章节写手 · ✨ 润色师 · 🔍 一致性审核员 · 📝 总结师 |
| **LangGraph4j 编排** | 多智能体状态图，支持中断挂起、断点续跑 |
| **全页面模型配置** | 页面添加/测试/切换 LLM endpoint，支持 OpenAI 兼容协议（DeepSeek / 通义 / Gemini / Ollama ...） |
| **角色-模型绑定** | 每个角色独立选模型 + 温度档位（creative / balanced / strict），不同章节交给不同模型写 |
| **异步生成** | 后台异步触发，前端实时轮询进度，多作品并行不阻塞 |
| **多端覆盖** | PC 桌面端 + 移动端 H5（手机访问自动跳 `/m` 独立页面）+ 微信小程序（Taro 实现） |
| **可观测性** | Actuator + Prometheus metrics（可选集成 Grafana 面板） |
| **Docker 一键部署** | docker compose up -d 全站就绪 |

## 🚀 快速开始（Docker 一键部署）

### 1. 准备环境变量

```bash
cp .env.example .env
# 编辑 .env 填写: PG_PASSWORD / OPENAI_API_KEY / OPENAI_BASE_URL / OPENAI_MODEL_NAME
```

### 2. 一键启动

```bash
docker compose up -d --build
```

首次启动会：
- 拉取 PostgreSQL 镜像（并自动创建 `novel_agent` 库）
- 编译 backend（Maven 多阶段构建）
- 编译 frontend（Vite 多阶段构建）
- Spring Boot 启动时自动执行 `schema.sql` 建表

### 3. 访问

| 服务 | URL |
|---|---|
| **前端页面（PC）** | http://localhost |
| **移动端 H5** | http://localhost/#/m/home （手机访问首页自动跳转） |
| 后端 API | http://localhost/api |
| Actuator 健康检查 | http://localhost/api/actuator/health |
| Prometheus metrics | http://localhost/api/actuator/prometheus |

### 4. 配置模型

1. 打开 http://localhost → 左侧「模型配置」
2. 点击新增：填名称、LLM 地址、API Key、模型名
3. 点**测试连接**验证
4. 勾选 **设为 Active**
5. 左侧「角色-模型绑定」→ 为 6 个角色分别选模型和档位 → 保存

> ✅ 配置变更**即时生效**，不需要重启后端。

## 💻 本地开发

```bash
# ===== 1. 启 PostgreSQL =====
docker run -d --name pg \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=novel_agent \
  -p 5432:5432 \
  postgres:16-alpine

# ===== 2. 后端 =====
cd backend
mvn spring-boot:run
# http://localhost:8080/api

# ===== 3. 前端 =====
cd frontend
npm install
npm run dev
# http://localhost:5173 (Vite dev proxy → :8080)
# 手机端访问同一地址会自动跳移动端 H5 页面 (/m/home)

# ===== 4. 微信小程序 (可选) =====
cd miniprogram
npm install
npm run build:weapp
# 微信开发者工具「导入项目」选择 miniprogram/ 目录
# AppID 可用测试号; 详情→本地设置勾选「不校验合法域名」
# 手机与电脑同一 WiFi 即可真机调试内网后端接口
```

### 移动端 H5 说明

- 独立路由组 `/m/*`（首页 / 工坊 / 我的 / 创建作品 / 作品详情 / 章节复审），UI 与桌面端完全隔离，互不干扰
- 手机 UA 或视口 < 768px 访问 `/novel` 时自动跳 `/m/home`
- 移动端仅覆盖写作核心流程，模型配置 / 角色绑定仍在 PC 端操作

### 微信小程序说明

- 6 个页面：首页 / 工坊 / 我的 / 创建作品 / 作品详情 / 章节复审，功能与移动端 H5 一致
- 后端地址在 `miniprogram/src/services/api.ts` 顶部 `BASE_URL` 配置，默认 `http://192.168.124.40:8080/api`，改成本机局域网 IP 即可
- 真机调试需手机与电脑同一 WiFi，微信开发者工具勾选「不校验合法域名」

### 后端端口 / Context Path

后端 `server.port=8080`, `server.servlet.context-path=/api`。前端 Vite dev proxy 已配置 `/api → http://localhost:8080`，无需额外设置。

### 配置文件

| 文件 | 说明 |
|---|---|
| `backend/src/main/resources/application.yml` | 后端主配置（DB / LangChain4j / novel 档位参数） |
| `backend/src/main/resources/schema.sql` | 建表脚本，启动时自动执行（幂等 `CREATE TABLE IF NOT EXISTS`） |
| `docker-compose.yml` | 生产部署编排 |
| `.env` | 环境变量 |

> `schema.sql` 由 `application.yml` 中的 `spring.sql.init.mode=always` 触发。Spring Boot 该配置默认为 `embedded`，
> 对 PostgreSQL 这类非内嵌库不会执行，因此必须显式设为 `always`。
> 脚本只负责建表，**不负责创建 database**：Docker 部署由 `POSTGRES_DB` 自动建库，本地开发需自行确保 `novel_agent` 库已存在。
> 脚本内容全部为 `IF NOT EXISTS`，每次启动重复执行无副作用。

## 🎯 Agent 角色说明

| 角色 | 默认档位 | 职责 |
|---|---|---|
| 🌍 `world-builder` | creative | 根据用户一句话创意 → 世界观 / 时代 / 势力 / 地理 |
| 📐 `outline-architect` | strict | 世界观 → 多卷大纲 + 每章核心事件 |
| ✍️ `chapter-writer` | creative | 按大纲逐章写正文（2000 字目标） |
| ✨ `chapter-polisher` | balanced | 语言润色、节奏调整、感官细节补充 |
| 🔍 `consistency-reviewer` | strict | 人设/时间线/道具前后矛盾检查，不过则打回重写 |
| 📝 `summary` | balanced | 每章结束生成滚动摘要，喂给下一章 context |

> **档位含义**（可在页面覆盖）：
> - `creative`: temperature=0.9 / timeout=300s / max_tokens=4000
> - `balanced`: temperature=0.7 / timeout=180s / max_tokens=2500
> - `strict`: temperature=0.2 / timeout=240s / max_tokens=2000

## 📊 数据库表（5 张）

```
t_model_config          — 模型接入点 (支持多条, 页面管理)
t_model_role_binding    — 角色-模型绑定 (每个 agent_role 唯一)
t_novel_project         — 小说项目主表 (设定/大纲/状态)
t_novel_chapter         — 章节正文 (章节号唯一, 审核状态)
t_novel_agent_log       — Agent 执行日志 (输入/输出/耗时)
```

主键全部 `GENERATED BY DEFAULT AS IDENTITY`（自增），MyBatis-Plus `IdType.AUTO` 自动回填。
